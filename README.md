# Редактор лутфильтра для Path of Exile 2

Визуальный редактор `.filter`: предметы раскладываются по тирам по рыночным ценам, для каждого тира настраивается стиль, результат скачивается готовым файлом.

Цены валюты и уников берутся с poe.ninja, популярность баз — из билдов poe.ninja, исключительные вещи (лишние гнёзда, качество) ищутся на официальном трейде.

Все эти данные собирает и хранит сервер; пользователи редактора только читают сохранённое и сами ничего не запускают (см. «Сбор данных»).

## Разработка

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev      # http://localhost:5173
npm test
```

После патчей игры справочник баз обновляется командой `npm run update-bases`, а следом русские названия предметов — `npm run update-names` (именно в таком порядке: названия собираются для баз из справочника).

Интерфейс на двух языках, русском и английском; надписи лежат в `src/i18n.ts`. В самом файле фильтра названия предметов всегда английские — так их понимает игра.

В разработке расписание сбора данных не работает: цены и популярность подтягиваются с poe.ninja при первом запросе и сохраняются в `data/`, а трейд опрашивается только служебным запросом (см. «Сбор данных»).

## Деплой

`npm run build` собирает две части:

- `dist/` — страница;
- `dist-server/index.js` — сервер одним файлом, без зависимостей: раздаёт страницу и обслуживает `/api/`.

На сервере достаточно этих двух каталогов и Node.js; `node_modules` там не нужен.

### Одной командой с рабочего ПК

Нужны сервер с Docker и доступ к нему по SSH (root, пользователь из группы `docker` или с sudo). На рабочем ПК Docker не нужен.

Один раз скопируйте `deploy.config.example.json` в `deploy.config.json` и заполните. Дальше:

```powershell
npm run deploy
```

Сценарий прогоняет тесты, собирает проект, отправляет готовую сборку на сервер, собирает там Docker-образ и пересоздаёт контейнер. Если новая версия не отвечает, возвращается предыдущая.

Поля `deploy.config.json` (файл в репозиторий не попадает):

| Поле | Назначение |
|---|---|
| `server` | Адрес для SSH: `user@host`. |
| `domain` | Домен редактора. Если задан, рядом поднимается Caddy: он сам получает сертификат и отдаёт редактор по `https://домен`, а порт приложения наружу закрывается. DNS-запись домена должна указывать на сервер, порты 80 и 443 — быть свободны и открыты. Пусто — редактор доступен по HTTP на `port`. |
| `aliases` | Ещё домены с тем же редактором, например `["loot.example.org"]`. Настройки в браузере у каждого домена свои, поэтому это удобно при переезде: старый адрес работает, пока фильтры переносят через «Мои фильтры». |
| `redirects` | Домены, которые постоянно перенаправляют на `domain`, например `["www.example.com"]`. |
| `password` | Пароль входа (логин `loot`). Если задан, записывается на сервер при каждом деплое. Пусто — остаётся тот, что уже на сервере; при первом деплое создаётся случайный и один раз печатается в консоли. |
| `port` | Порт приложения на сервере (по умолчанию 8080). С доменом слушает только `127.0.0.1`. |
| `appDir` | Каталог на сервере (по умолчанию `/opt/loot-filter`). |
| `service` | Имя контейнера и образа (по умолчанию `loot-filter`). |

На сервере в `appDir` лежат:

- `.env` — логин и пароль;
- `data/` — собранные данные: цены, популярность баз, результаты опроса трейда;
- `caddy/` — настройки и сертификаты Caddy (только при заданном домене).

Повторные деплои `data/` и сертификаты не трогают. Метка образа — коммит и время деплоя; хранятся текущий образ и один предыдущий. Журналы: `docker logs loot-filter` и `docker logs loot-filter-caddy`.

Параметры командной строки: `-Server`, `-Domain`, `-AppDir`, `-Service`, `-Port` (вместо полей файла), `-SkipTests`, `-DryRun` (собрать и упаковать, на сервер не ходить). Передаются после `--`, например `npm run deploy -- -DryRun`.

### Docker вручную, из исходников

```bash
docker build -t loot-filter .
docker run -d --name loot-filter --restart unless-stopped \
  -p 8080:8080 \
  -e AUTH_PASSWORD='придумайте-пароль' \
  -v loot-data:/app/data \
  loot-filter
```

Редактор откроется на `http://<адрес-сервера>:8080`, логин — `loot`.

Обновление: `git pull`, затем снова `docker build`, `docker rm -f loot-filter` и `docker run` с теми же параметрами. Том `loot-data` при этом сохраняется.

### Без Docker

```bash
npm ci
npm run build
HOST=0.0.0.0 AUTH_PASSWORD='придумайте-пароль' npm start
```

Чтобы сервер переживал перезагрузку, запускайте его через systemd или pm2.

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | Порт сервера. |
| `HOST` | `127.0.0.1` | Интерфейс. Чтобы сервер был доступен извне, задайте `0.0.0.0` (в Docker-образе уже так). |
| `AUTH_PASSWORD` | не задан | Пароль (HTTP Basic). Без него редактор открыт всем, кто знает адрес. |
| `AUTH_USER` | `loot` | Логин. |
| `DATA_DIR` | `data` | Каталог с собранными данными. |
| `LEAGUES` | текущая лига poe.ninja | Лиги, для которых данные собираются по расписанию, через запятую. |
| `SCAN_INTERVAL_HOURS` | `24` | Как часто опрашивать трейд на исключительные вещи. |
| `EXCEPTIONAL_MIN_EXALTED` | `100` | Нижняя граница цены для опроса трейда, в exalted. |
| `ADMIN_TOKEN` | не задан | Ключ для служебных запросов. Пока не задан, они отключены. |
| `SCHEDULER` | включён | `off` отключает сбор данных по расписанию. |
| `STATIC_DIR` | `dist` | Каталог со страницей. |

### Сбор данных

Сервер сам собирает данные и хранит их в `DATA_DIR`; запросы пользователей отдают сохранённое.

| Данные | Откуда | Обновление |
|---|---|---|
| Список лиг | poe.ninja | раз в час |
| Цены валюты и уников | poe.ninja | раз в 30 минут |
| Популярность баз | билды poe.ninja | раз в 3 часа |
| Исключительные вещи | официальный трейд | раз в `SCAN_INTERVAL_HOURS` |

По расписанию обновляются лиги из `LEAGUES`. Если пользователь выберет другую лигу, её цены и популярность подтянутся с poe.ninja при первом запросе и тоже сохранятся; трейд для таких лиг не опрашивается.

Опрос трейда вне расписания может запустить только владелец сервера — запросом с ключом `ADMIN_TOKEN`:

```bash
# запустить (min — цена в exalted, по умолчанию EXCEPTIONAL_MIN_EXALTED)
curl -u loot:пароль -X POST -H "X-Admin-Token: ключ" "https://домен/api/admin/scan?league=Forbidden%20Rites&min=100"
# посмотреть ход
curl -u loot:пароль -H "X-Admin-Token: ключ" "https://домен/api/admin/scan"
# остановить
curl -u loot:пароль -X POST -H "X-Admin-Token: ключ" "https://домен/api/admin/scan/stop"
```

При деплое через `npm run deploy` переменные вписываются в `.env` в каталоге приложения на сервере (по строке `ИМЯ=значение`); деплой меняет в этом файле только логин и пароль. После правки запустите деплой ещё раз, чтобы контейнер пересоздался с новыми настройками.

### Что учесть

- **Пароль без HTTPS передаётся в открытом виде.** Для доступа через интернет поставьте перед сервером nginx или Caddy с HTTPS.
- **Лимиты трейда считаются по IP сервера.** Опрос запускает только расписание, раз в сутки; трейд может приостанавливать его, и тогда он длится до 40 минут.
- **poe.ninja и трейд стоят за Cloudflare** и могут не отвечать на запросы с IP дата-центров. Если после деплоя цены не грузятся, причина, скорее всего, в этом.
- **Настройки фильтра хранятся в браузере**, а не на сервере: в другом браузере или на другом устройстве они начнутся с настроек по умолчанию.
- **Собранные данные** лежат в `DATA_DIR`; при переносе на другой сервер скопируйте этот каталог.
